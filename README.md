# تيك زون - إصلاح التشغيل والحسابات والتصنيفات

## قبل النشر
1. نفّذ `database.sql` بالكامل في Supabase SQL Editor.
2. في Supabase: Authentication > Providers > Email، عطّل **Confirm email** إذا أردت أن يتم تسجيل الحساب ثم الدخول تلقائياً مباشرة من المتجر.
3. ارفع محتويات `digital-store` إلى GitHub Pages.

## ما تم إصلاحه
- إزالة تكرار مستند HTML في `index.html` الذي كان يسبب مشاكل DOM وحقول تسجيل الدخول.
- إصلاح تسجيل الدخول/إنشاء الحساب مع جلسة Supabase دائمة.
- إنشاء سجل `users` تلقائياً عبر Trigger وربطه بحساب Auth.
- إصلاح أعمدة المستخدمين والتجار والمنتجات والطلبات والتقييمات والتخزين المستخدمة فعلياً في المشروع.
- إضافة التصنيف الفرعي للمنتجات، بما في ذلك: ثلاجات، غسالات، عصارات، مكيفات وغيرها.
- إصلاح تمرير UUID للمنتجات داخل أزرار السلة والمفضلة.
- إضافة سياسات RLS والجداول الناقصة التي يعتمد عليها المشروع.

4. إذا أردت إنشاء جلسة زائر تلقائياً عند فتح المتجر، فعّل **Anonymous Sign-Ins** من Supabase Authentication. إذا كانت الميزة غير مفعلة، يستمر المتجر بدون جلسة زائر ويطلب إنشاء حساب عند الشراء/الحساب. الحساب المجهول مرتبط بالمتصفح، والحساب الدائم يتم إنشاؤه بالبريد وكلمة المرور قبل الشراء.

## التحديث الحالي — مهم جداً

إذا كنت قد نفذت `database.sql` السابق بالفعل **ولا تريد حذف البيانات الحالية**، لا تعيد تشغيل `database.sql`.

نفّذ الملف:

`database_upgrade.sql`

هذا الملف ترقية غير مدمرة تضيف:
- إتمام طلبات آمن من الخادم عبر RPC مع إعادة حساب الأسعار والمخزون.
- منع التلاعب بسعر المنتج من المتصفح.
- عمولات التاجر تُحسب من قاعدة البيانات وليس من JavaScript.
- تسجيل العمولات في `transactions` وفواتير التجار في `vendors.current_invoice`.
- عكس العمولة وإرجاع المخزون عند إلغاء الطلب.
- صلاحيات منفصلة للأدمن والتاجر والعميل.
- مراجعة منتجات التجار قبل نشرها.
- صورة رئيسية وصور فرعية للمنتج.
- حماية إثباتات الدفع كملفات خاصة بدلاً من روابط عامة.
- حماية حساب الأدمن من رفع الصلاحية عبر بيانات التسجيل.
- إعادة تحميل PostgREST schema cache تلقائياً.

### دورة العمولة

عند تأكيد التاجر لحصته من الطلب، تحسب القاعدة العمولة وفق `vendors.commission_rate` وتضيفها إلى `current_invoice` وتسجلها في `transactions`.
عند وصول الفاتورة إلى `invoice_limit` يصبح التاجر مقيداً حتى يتم السداد من لوحة الأدمن.
عند السداد يستخدم الأدمن `settle_vendor_invoice`، وهي دالة محمية ولا يمكن استدعاؤها بنجاح إلا من حساب أدمن.

### إعدادات Supabase المطلوبة

1. Authentication → Providers → Email: إذا أردت التسجيل ثم الدخول فوراً، عطّل Confirm email.
2. Authentication → Sign In / Anonymous: فعّل Anonymous Sign-ins إذا أردت إنشاء جلسة زائر تلقائياً.
3. Storage: ملف الترقية ينشئ/يحدث `product-images` و`payment-proofs`. صور المنتجات عامة للعرض، وإثباتات الدفع خاصة ومقيدة بالصلاحيات.
4. لا تضع `service_role` key داخل ملفات الواجهة. المشروع يستخدم publishable/anon key فقط.
